# EduJournal

## Этап 40%: справочники, аккаунты и журнал

После запуска приложения Flyway применяет новые миграции V8–V11. Существующие
расписания и аккаунты сохраняются. Назначения учителей из уже существующих уроков
переносятся в журнал при применении V8.

- `/management` — директор создаёт классы, предметы, учебные годы с четырьмя
  четвертями, аккаунты учителей, учеников и родителей, назначения на класс и предмет.
  Владелец выбирает школу и создаёт аккаунты директоров.
- `/journal` — учитель видит назначенные классы и предметы, директор — свою школу,
  ученик — только свои оценки, родитель — только подтверждённых детей.
- `/journal/today` — явный сценарий «Выставить оценки»: урок → список учеников →
  оценка 1–5 → сохранение. Другая дата доступна только для просмотра. Отсутствие
  четверти, назначения или аккаунтов учеников объясняется на странице уроков.
- `/journal?family=true` — учитель просматривает оценки собственных детей как родитель.

Порядок настройки директором:

1. Откройте «Управление школой» из кабинета или расписания. Создайте классы и предметы.
2. Создайте учебный год и четыре четверти. Все четверти должны находиться внутри года,
   идти по порядку и не пересекаться; интервалы каникул разрешены.
3. Создайте аккаунты с уникальными цифровыми логинами. Ученику обязательно назначьте
   класс. Учителю можно выбрать существующий профиль из расписания или создать новый
   по ФИО. Выдайте логин и пароль пользователю лично.
4. Назначьте учителя на класс и предмет, затем создайте уроки в расписании.
5. Для родителя укажите точный логин и выберите ученика после проверки сведений школы.
   Можно связать одного родителя с несколькими детьми, в том числе из разных школ,
   и несколько родителей с одним ребёнком. Отзыв связи сразу прекращает доступ.
6. Учитель открывает журнал и сохраняет целые оценки 1–5 за уроки текущего дня по
   времени Кыргызстана. Для подгрупп проверяется членство ученика. В выбранной четверти
   или вкладке «Год» учитель отдельно выбирает и подтверждает итоговую оценку.

Сохранённые текущие и итоговые оценки нельзя исправить или отменить. Повторная отправка
той же оценки не создаёт дубликат; попытка записать другую отклоняется. PostgreSQL
дополнительно защищает оценки триггерами от UPDATE/DELETE и запрещает изменение урока
с оценками. Среднее не вычисляется как итог автоматически. Если для даты урока нет
учебной четверти, сохранение оценки отклоняется с объяснением.

Если кнопки сохранения оценки нет, откройте `/journal/today`: там показываются уроки
учителя и причина недоступности ввода. Проверьте учебные периоды, профиль преподавателя,
назначение на класс и предмет, аккаунты учеников в классе и дату урока. Численность класса
сама по себе не создаёт аккаунты учеников. Существующий аккаунт можно настроить в
`/management#profiles`. Даты четвертей задаёт директор по календарю своей школы.

Новые экраны используют предоставленный пользователем пример: светлый фон, боковое меню,
карточки и цветные оценки. Ссылка на исходный Figma-файл хранится в `AGENTS.md`.
Архивирование годов, посещаемость, домашние задания, уведомления и графики относятся к
следующим этапам таблицы ТЗ.

Проверка нового этапа:

```powershell
.\mvnw.cmd '-Dtest=AcademicTests' test
```

Отдельная проверка миграций и запретов изменения оценок на PostgreSQL:

```powershell
$env:EDUJOURNAL_VERIFY_POSTGRES = 'true'
$env:DB_URL = 'jdbc:postgresql://localhost:5432/tkrpo'
$env:DB_USER = 'postgres'
$env:DB_PASSWORD = 'ваш пароль'
.\mvnw.cmd '-Dtest=PostgresGradeTests' test
```

Этот тест создаёт временную схему с уникальным именем `academic_check_...`, проверяет
миграции и триггеры и удаляет только эту схему. Рабочие таблицы не затрагиваются.
Без `EDUJOURNAL_VERIFY_POSTGRES=true` данный тест пропускается; остальные работают на H2.

Электронный журнал с авторизацией, ролями и расписанием на полугодие.

## Запуск

Нужны Java 21 и PostgreSQL. Дополнительные профили не требуются:

```powershell
.\mvnw.cmd clean spring-boot:run
```

Откройте http://localhost:8080/login и войдите под аккаунтом из таблицы `users`.
Расписание доступно по адресу http://localhost:8080/schedule.
В IntelliJ IDEA выберите SDK и Maven JDK 21, поле Active profiles оставьте пустым.

Подключение можно переопределить переменными окружения:

```powershell
$env:DB_URL = "jdbc:postgresql://localhost:5432/tkrpo"
$env:DB_USER = "postgres"
$env:DB_PASSWORD = "ваш пароль"
.\mvnw.cmd spring-boot:run
```

Схему создаёт Flyway, Hibernate проверяет её через `ddl-auto: validate`.
Уже применённые миграции изменять нельзя: изменения оформляются новой миграцией.

## Роли и школы

| Роль | Расписание |
| --- | --- |
| OWNER | Выбирает школу и просматривает её расписание |
| DIRECTOR | Просматривает, создаёт и редактирует расписание своей школы |
| TEACHER | Просматривает расписание школы; фильтр «Только мои уроки» показывает занятия преподавателя из аккаунта |
| STUDENT | Просматривает только расписание своего класса |
| PARENT | Просматривает расписание своей школы |

У владельца `school_id` должен быть `NULL`, у остальных — ID существующей школы.
Пароли хранятся в формате BCrypt. Школа определяется по аккаунту;
передача ID другой школы не даёт доступа к её данным. Владелец может выбрать существующую школу для просмотра.
POST-запросы защищены CSRF-токеном Spring Security. Выход выполняется POST-формой.

Тестовые аккаунты и справочники при обычном запуске не создаются. Существующие данные PostgreSQL сохраняются.
Справочники: `schedule_school`, `schedule_class`, `schedule_subgroup`, `schedule_membership`,
`schedule_subject`, `schedule_teacher`, `schedule_room`.
Если классов нет, страница показывает сообщение о пустом справочнике.
Классы и предметы создаются директором на `/management`; кабинеты, подгруппы и членство
в подгруппах пока настраиваются в БД.
Профиль учителя связывается с `schedule_teacher` через `users.teacher_id`, профиль ученика —
с `schedule_class` через `users.student_class_id`. Ссылки проверяются в пределах школы.
Без назначенного класса ученик не получает доступ к расписанию; без профиля преподавателя
учителю недоступен персональный фильтр. Родителю пока доступно общее расписание школы.

Предметы преподавателя перечислены в `schedule_teacher_subject(school_id, teacher_id, subject_id)`.
У одного преподавателя может быть несколько профильных предметов, например математика, алгебра
и геометрия. Директор выбирает предмет, затем преподавателя из соответствующего списка.
Сервер и внешний ключ БД запрещают назначать преподавателя на предмет вне его списка.
Изменять расписание по-прежнему может только директор.

## Структура пакетов

Все пакеты находятся внутри `com.example.edujurnal`:

| Пакет | Назначение |
| --- | --- |
| `controller` | HTTP-маршруты и модели страниц |
| `service` | Бизнес-логика, доступ, расписание и попытки входа |
| `repository` | Доступ к БД через JPA и JDBC |
| `entity` | Сущности JPA и роли |
| `dto` | Формы и модели расписания на полугодие |
| `exception` | Исключения и общий обработчик ошибок |
| `security` | Обработчики входа |
| `config` | Настройки безопасности, паролей и времени |
| `util` | Школьная сетка звонков |

## Расписание

Расписание отображается одной сеткой с понедельника по пятницу на выбранное полугодие,
без выбора недель. Можно выбрать класс и полугодие. Первое полугодие — сентябрь–декабрь,
второе — январь–май. В каждом дне до шести уроков. Время рассчитывается сервером по номеру урока,
часовой пояс — `Asia/Bishkek`. Повторяющаяся серия отображается один раз, с ближайшим предстоящим
занятием для редактирования. Завершённые занятия сохраняются в БД.

| Урок | Время | Перемена после урока |
| --- | --- | --- |
| 1 | 08:00–08:45 | 5 минут |
| 2 | 08:50–09:35 | 5 минут |
| 3 | 09:40–10:25 | 15 минут |
| 4 | 10:40–11:25 | 5 минут |
| 5 | 11:30–12:15 | 5 минут |
| 6 | 12:20–13:05 | — |

При добавлении урока период по умолчанию заканчивается в конце полугодия.
При редактировании по умолчанию меняются все оставшиеся занятия этой серии в полугодии;
можно выбрать разовое изменение. При конфликте откатывается вся серия изменений.
Начавшиеся уроки не редактируются. Проверяется вместимость кабинета для целого класса.

Проверяются пересечения учителей, кабинетов, классов и общих учеников подгрупп.
Соседние уроки допустимы. Версии записей защищают от сохранения устаревшей формы,
а токен создания — от дублирования при повторной отправке.
Блокировка строки школы защищает проверку и запись от конфликтующих одновременных запросов.
Старые уроки с произвольным временем отображаются отдельно от сетки звонков.

## Данные для показа

В текущую школу добавлен вымышленный пример: классы 5А–11Б (14 классов, суммарная
наполняемость 392 ученика), 29 преподавателей, 20 предметов и 22 кабинета.
Вместимость кабинетов — 32–60 мест. В обычной сетке 410 занятий: 27 для каждого 5-го класса,
28 для 6-го и по 30 для 7–11-х классов. Датированные занятия охватывают все будни текущего полугодия.
Это пример наполнения, а не утверждённый учебный план или календарь каникул.

Генератор запускается вручную и не подключён к старту приложения:

```powershell
node scripts/generate-school-data.cjs
psql -h localhost -p 5432 -U postgres -d tkrpo -v ON_ERROR_STOP=1 -v school_id=1 -f target/school-showcase.sql
```

Перед заполнением запустите приложение для применения миграций. Генератор сохраняет SQL
в `target/school-showcase.sql`; транзакция проверяет пересечения и вместимость до записи уроков.
Повторный запуск не создаёт дубликаты. При пересечении с существующими занятиями вся загрузка
откатывается. Существующие аккаунты и вручную изменённые уроки не перезаписываются.

Для существующего вымышленного примера после применения V6 можно настроить специальности
и связать имеющиеся аккаунты:

```powershell
node scripts/generate-school-data.cjs
psql -h localhost -p 5432 -U postgres -d tkrpo -v ON_ERROR_STOP=1 -v school_id=1 -f scripts/configure-showcase-profiles.sql
```

Этот отдельный скрипт сверяет профильные предметы вымышленных преподавателей, переназначает
ошибочные серии свободному специалисту по тому же предмету и не меняет даты занятий.
Он связывает `teacher1` с Петровым Дмитрием Андреевичем (математика, алгебра, геометрия),
а `student1` — с 5А. Настроенные профили и пароли не перезаписываются. Для реальных аккаунтов
при создании аккаунта директор выбирает профиль учителя или класс ученика на `/management`.
Первичная настройка существующих аккаунтов доступна в разделе «Учебные профили»
на `/management#profiles`. После появления оценок смена профиля здесь блокируется,
чтобы не исказить историю; перевод ученика между классами требует отдельной процедуры.

## Проверка

```powershell
.\mvnw.cmd clean test
```

Тесты используют изолированную H2 в памяти. Справочники находятся в
`src/test/resources/schedule-fixtures.sql` и не попадают в рабочую БД.
Проверяются авторизация, права ролей, изоляция школ, CSRF, рендеринг страниц,
уроки, повторы, конфликты, устаревшие формы и конкурентные изменения.
