# EduJournal — ручное расписание

Реализован этап 20% Шайкинова Б. из обновлённого ТЗ: ручное создание и редактирование уроков, проверка пересечений класса / учеников подгрупп, учителей и кабинетов.

## Запуск для демонстрации

Нужна Java 21. В PowerShell из корня проекта:

```powershell
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=demo"
```

Откройте http://localhost:8080/schedule.

Деморежим содержит два класса, три подгруппы, три предмета, три учителя и три кабинета. Уроки создаются через кнопку «Добавить урок», сохраняются в файловой базе H2 `data/schedule.mv.db` и остаются после перезапуска. База исключена из Git. Даты и время трактуются по `Asia/Bishkek`.

## Недельное расписание

Для каждого класса выводится отдельная таблица: пять столбцов с понедельника по пятницу и шесть строк уроков. Можно показать все классы или выбрать один, переключаться между неделями и добавлять урок непосредственно в ячейку с уже выбранными классом, датой и номером.

| Урок | Время | Перемена после урока |
| --- | --- | --- |
| 1 | 08:00–08:45 | 5 минут |
| 2 | 08:50–09:35 | 5 минут |
| 3 | 09:40–10:25 | 15 минут |
| 4 | 10:40–11:25 | 5 минут |
| 5 | 11:30–12:15 | 5 минут |
| 6 | 12:20–13:05 | — |

Время рассчитывается сервером по номеру урока. Пустая ячейка означает, что предмет ещё не назначен; автоматического заполнения предметами нет. Параллельные уроки независимых подгрупп показываются в одной ячейке.

При создании включено «Повторять каждую неделю в этот день». Укажите дату первого урока и конец периода включительно (например, конец четверти). По умолчанию форма предлагает три месяца, предел периода — один год. Снятая галочка создаёт разовый урок. Сервер сохраняет все даты одной транзакцией; при конфликте на любой неделе откатывается вся серия с указанием проблемной даты.

У повторяющегося урока можно изменить только выбранное занятие либо его и все последующие повторения. При массовом изменении даты сохраняются; перенос даты выполняется для отдельного урока. Проверяется актуальность всей серии, чтобы не затереть изменения из другой вкладки. Начавшиеся уроки не изменяются.

Старые записи с произвольным временем или в выходные сохраняются и отображаются под таблицами выбранной недели в разделе «Уроки вне новой сетки звонков». При редактировании их нужно привести к буднему дню и одному из шести номеров урока.

Для запуска из IntelliJ IDEA: Project SDK / Maven JDK — 21; активный Spring-профиль — `demo` (или переменная окружения `SPRING_PROFILES_ACTIVE=demo`).

## Что проверяется

- Все обязательные поля и принадлежность справочников школе; подгруппа принадлежит выбранному классу.
- Начало раньше окончания; создание и перенос разрешены только на будущее время.
- Начавшийся или проведённый урок нельзя редактировать.
- Пересечение времени проверяется по условию `начало A < конец B && начало B < конец A` в одну дату. Поэтому 09:00–09:45 и 09:45–10:30 совместимы.
- Один учитель и один кабинет не могут использоваться одновременно.
- Весь класс конфликтует с любой своей подгруппой; одна подгруппа — сама с собой.
- Разные подгруппы конфликтуют при наличии общих учеников с действующим на дату урока членством. Границы членства включительны.
- При редактировании текущая запись исключается из проверки конфликтов. При ошибке исходный урок сохраняется.
- Повторная отправка создания с тем же токеном не создаёт копию.
- Версия записи защищает от сохранения устаревшей формы.
- Блокировка строки школы в транзакции объединяет проверку и запись: два одновременных запроса не могут сохранить конфликтующие уроки. Все будущие способы изменения расписания должны использовать тот же протокол.

Сообщения о конфликтах показывают причину, номер и время уже существующего урока.

## Границы этапа и интеграция

Использована сущность «Урок» с конкретной датой из диаграммы классов; еженедельные повторения объединяются идентификатором серии. Генерация, публикация версий расписания, отмена, уведомления, журнал и управление справочниками относятся к последующим этапам и здесь не реализованы. Для самостоятельной разработки ТЗ допускает тестовые данные.

Вход, роли и правило трёх попыток относятся к параллельной работе Сагынбекова. Этот модуль не реализует аккаунты. `ScheduleController` доступен **только в профиле `demo`**, использует фиксированную демонстрационную школу и не является кабинетом с авторизацией. Сервер по умолчанию слушает только `127.0.0.1`.

При объединении с модулем доступа:

1. Подключить рабочий контроллер к `ScheduleService.savePlan`: получать `schoolId` из проверенной сессии, проверять роль директора на каждом чтении / изменении и включить CSRF-защиту Spring Security. Демоконтроллер оставить только для локальной проверки. Метод `save` остаётся низкоуровневой операцией для датированных уроков и проверки произвольных пересечений; недельный интерфейс использует `savePlan`, который задаёт фиксированные звонки.
2. Согласовать общие сущности школы, класса, учителя, предмета, кабинета и состава подгрупп. Таблицы с префиксом `schedule_` сейчас являются минимальными справочниками этого модуля; их наполняет исключительно демомиграция. Управления справочниками через интерфейс нет.
3. Добавить проверку назначений учителей, когда появится соответствующий модуль этапа 40%.
4. Подключить общий механизм процедур ввода с ограничением трёх ошибок из ФР 02.

Школа передаётся в методы сервиса явным параметром. Сервис проверяет принадлежность записей, но сам не устанавливает личность и роль пользователя.

## PostgreSQL

Без профиля `demo` приложение использует PostgreSQL и применяет только миграции схемы `db/migration`; тестовые справочники не создаются, веб-контроллер деморежима отключён.

Параметры подключения задаются переменными:

```powershell
$env:DB_URL = "jdbc:postgresql://localhost:5432/mydatabase"
$env:DB_USER = "myuser"
$env:DB_PASSWORD = "secret"
.\mvnw.cmd spring-boot:run
```

Для PostgreSQL из имеющегося `compose.yaml`:

```powershell
docker compose up -d
docker compose port postgres 5432
```

В `DB_URL` укажите порт, выведенный второй командой: Compose назначает его динамически. База должна быть запущена заранее; автоматический запуск Docker из приложения выключен.

Схема создаётся Flyway, JPA проверяет её через `ddl-auto: validate`. Не включайте профиль `demo` на рабочей базе: он предназначен для отдельной локальной базы и тестовых справочников.

## Проверка

```powershell
.\mvnw.cmd test
```

Автотесты используют изолированную H2 в режиме совместимости с PostgreSQL. Проверяются база, конкурирующие транзакции, HTTP-запросы с рендерингом Thymeleaf, недельная сетка, повторения и полный откат серии при конфликте на поздней дате. Проверка в реальном PostgreSQL пока не выполнена.

Ручной сценарий:

1. Выберите будущую неделю; добавьте в понедельник урок №1 класса 7А, учитель Иванова, кабинет 101. Включите повторение на три недели.
2. Создайте пересекающийся урок 7Б с тем же учителем — получите ошибку занятости учителя.
3. Поменяйте учителя, оставив кабинет 101, — получите ошибку занятости кабинета.
4. Выберите 7А, другого учителя и кабинет — получите ошибку пересечения класса.
5. Урок №2 (08:50–09:35) класса 7А должен сохраниться.
6. На другой дате создайте одновременно группы 1 и 2 класса 7А с разными учителями и кабинетами — это допустимо. Группа «Английский — продолжающие» пересекается с обеими по составу учеников.
7. Откройте один урок в двух вкладках. Измените и сохраните в первой; сохранение старой формы во второй должно завершиться сообщением об устаревшей версии.
8. Перейдите на следующую неделю: повторяющийся урок уже присутствует. Измените его кабинет с выбором «Этот и все последующие повторения»: предыдущая неделя должна остаться прежней.
